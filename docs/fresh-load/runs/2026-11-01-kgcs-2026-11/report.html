The build was preceded by a repository review and a cleanup; the review is what made the load safe. Comparing feed versions against the September snapshot before loading showed CWE had moved from 4.20 to 5.0 and changed its XML namespace. The loader had the namespace hard-coded and would have reported success with zero weaknesses. One commit later (803dc01: namespace read from the root element, zero weaknesses fail the step) the catalog loads 984 weaknesses and 1,278 consequences.

The second lesson came from the shell, not the data: a PowerShell pipeline whose log redirection failed left a loader process alive, invisible, surviving a DROP/CREATE DATABASE and racing the real run. Killed, recreated, re-run: this report describes a single-process build.

Why a new database
MERGE is idempotent for what exists but never deletes what upstream retired, so reloading over kgcs-v12 could not yield a clean delta. kgcs-v12 stays as the spec 1.2.1 reference; kgcs-2026-11 is November.

Findings

Six things surfaced by looking closely

F1
CWE 5.0 moved the catalog namespace fixed · 803dc01
cwe-7 → cwe-8. load_cwe.py had it hard-coded and would have iterated zero Weakness elements and reported success. Now the namespace is read from the root element and zero weaknesses fail the step; three tests cover it. CWE 5.0 also removes Category (422 → 0) for Groupings/Dimensions (431/395) — a spec-level decision, not loaded today.
F2
October ATT&CK release: +7 / −2 techniques verified
New: T1696 Anti-Automation Evasion (2 subs), T1697 Steal Application Specific Passwords, T1698 Indirect Prompt Injection, T1699 Direct Prompt Injection, T1700 AI-Enabled Exfiltration (enterprise), T1476 (mobile), T1701 Command and Scripting Interpreter (ICS, 6 subs) replacing T0807 and T0853. 378 + 7 − 2 = 383 and PART_OF 436 + 5 = 441, which is the "FAIL" against the September expected file and a PASS against today's. ATT&CK now has native AI techniques next to ATLAS.
F3
Three consequence values outside the spec 1.2.1 vocabulary spec backlog
CWE 5.0 introduces DoS: Prevent Access (CWE-1260-C1, CWE-1476-C1 — the latter a new weakness) and Undefined Behavior (CWE-1335-C2). Loaded verbatim as designed; both the Cypher check and SHACL flag them. The fix is a vocabulary update in kgcs-spec and a pin bump — the only red check of the run.
F4
One ADAPTED_FROM warning, known and legitimate known
AML.T0073 Impersonation cites T1656, revoked in the bundle (revoked-by → T1684.001, same name). The loader remapped and reported it; same case as spec-v1.2-deltas.md §"44, not 43". Confirmed in enterprise-attack.json.
F5
A second loader process was alive during the first attempt procedure
A PowerShell pipeline whose Tee-Object failed to open its file still started python.exe; it survived DROP/CREATE DATABASE (driver retries) and raced the real run — visible as DeadlockDetected retries between two clientIds, in a loader that has no concurrency. Killed, database recreated, re-run from zero. The procedure now checks Get-Process python* before launching and after cancelling.
F6
The cpe step took 71 minutes (≈45 in September) not diagnosed
For +4.7 % more MATCHES_PLATFORM. Same Neo4j instance also hosts kgcs-v12 and kgcs-demo; no Bolt-level timing was kept. Worth a look before the next run, not before this one.
Scope

What this pass does not claim

  • Raw download byte total — download.log not kept; recorded only "13/13 standards dated today" and the per-feed version diff.
  • Cause of the slower cpe step (F6).
  • Neo4j server version taken from the instance already hosting kgcs-v12, not read from the server during this run.
  • CAUSED_BY provenance read by hand on two CVEs; the Cypher check caused_by_provenance_aligned covers all 362,316.
  • kgcs-server was not pointed at this database: its spec pin is still 1.0.0 and knows nothing of KEV, EPSS, SSVC or ATLAS.
  • Chain coverage is measured at the CVE → CWE hop; CWE → CAPEC → ATT&CK coverage is unchanged from the September report and was not re-measured.
